# 分类法（taxonomy）

**本文件是钩子类型和领域枚举的唯一事实源。** 新增视频时从中选值；要新增枚举值时，按文末同步规则三处一起改。

## 钩子类型（单选）

| 类型 | 定义 | 典型开场 |
|------|------|----------|
| 成果前置 | 第一句/第一个画面直接给成品或反常识新事实 | 「Zotero 现在是 Codex 里的一个插件了」「我又找到一个 X」 |
| 需求宣告 | 宣告内容来自观众呼声，需求已验证 | 「今天是大家最需要的一期」 |
| 教学宣告 | 直给"今天教你 X"，承接关注者期待 | 「今天来教大家如何做自己的 skill」 |
| 故事切入 | 具体场景/亲历故事带出话题，常配社会证明 | 「我在日本书店发现卖教 AI 工具的书」 |
| 背景铺垫（弱） | 创作者视角先讲自己的经历，钩子出现晚 | 「最近参加了比赛，花了很多心思……」 |

判定规则：看**前 5 秒**给观众的是什么。注意"（弱）"后缀表示该形态数据表现弱，标注它是为了统计钩子类型与数据的关系。

## 领域（单选）

| 领域 | 覆盖范围 |
|------|----------|
| AI+科研工具 | 文献管理、科研 AI 工具、效率工具（Zotero/Codex/Skill 类） |
| AI+演示制作 | HTML/PPT 演示文稿制作 |
| AI+开发教学 | 教观众做工具/skill/agent 的内容 |
| AI+学习方法 | AI 时代的学观点与方法论 |
| AI+论文写作 | 论文写作、审稿、投稿 |
| AI+内容创作 | 拆解爆款、涨粉、选题、账号运营、自媒体工作流（2026-08-30 新增） |
| 其他 | 不属于以上时先用这个，积累 2 条以上再提新领域 |

## 新增枚举值的三处同步规则

新增值时必须**同时**改三处，顺序如下：

1. **本文件**：加进上表并写清定义
2. **Base 字段**：`bitable_write.py` 会自动检测并补选项（field-update PUT 全量），无需手动；但新值的定义要先写进本文件再入库
3. **analysis-rubric / analyses**：之后的新分析才能使用新值；旧分析不改

反例（已发生过）：先在分析里写了「故事切入」，Base 没有这个选项 → 写入报错。正确顺序是先改本文件。
