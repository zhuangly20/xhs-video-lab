# 拆解分析框架（analysis-rubric）

本文件规定 analyses/<id>.json 的 schema 和分析质量硬约束。**分析是这个工作流里唯一由 LLM 判断的环节，口径一致性全靠这份文件。**

## JSON Schema（完整示例）

```json

  "url": "https://www.xiaohongshu.com/explore/6a1ec4cf000000002202ccf4",
  "duration": 164,
  "publishedAt": "2026-06-02",
  "collectedAt": "2026-08-30",
```

## 各环节硬约束

### hook（钩子拆解）
- `quote` 必须是逐字稿原文（前 20 秒内）
- `type` 参照 taxonomy.md 的钩子类型，可在类型后加副标注（如"成果前置 / 反常识事实"）
- `explain` 必须回答：这个开头为什么能让观众停下来（或为什么留不住人）。写机制，不写感受

### structure（结构时间轴）
- 5-10 个节点，覆盖钩子→主体→CTA 全程，每节点标时间
- 长视频（>300s）节点按内容模块划分，不按句子

### strengths / weaknesses（优劣势）
- 各 2-4 条，**每条必须挂具体证据**：秒数、数字、原文引用、或与其他案例的对比
- 允许句式：「84秒零废话，全程屏幕演示」✓；禁止：「内容优质，节奏流畅」✗
- weaknesses 要说真话：数据差的视频直说差在哪，不粉饰

### dataInsight（数据解读）
- 必须用到收藏赞比（collects/likes，构建时自动算）并解释内容属性：
  - ≥1.5 强工具型（存着照做）；1.0-1.5 中性；<1 围观/观点型（认同转发）
- 有对照组时必提（如同博主不同形态、同时长不同钩子）

### scripts（可复用话术）
- 2-4 条，每条 = 句式模板（X/Y 占位）+ 适用场景
- 标准是"读者明天拍自己的视频能直接套用"

### tags（标签）
- 4-6 个，混合：领域 + 钩子类型 + 内容形态（纯录屏/口播出镜/教程/观点）+ 特色（强CTA/金句高密度/极短时长）

## 运营经验（insights.json）更新规则

- 触发时机：未被引用的新案例累计 ≥3 条
- 形态：`{"insights": [{"title", "detail", "sources": [案例id]}]}`
- 4-8 条，每条必须是对**全部案例交叉比较**得出的可执行结论，标注佐证案例
- 好的经验长这样：「时长与传播量明显负相关：84秒赞1.3万 vs 311秒赞434，甜点区60–140秒」
- 坏的经验（禁止）：「要注重内容质量」「标题很重要」——不可执行的废话

## 数据来源说明

- id/标题/时长/互动数据/发布时间：阶段 1 pipeline.py 输出的 PIPELINE_RESULT JSON，直接抄
- collectedAt：今天（入库日期，格式 YYYY-MM-DD）
- quote 类字段：从 transcripts/<id>.txt 找原文，注意转录同音错别字
